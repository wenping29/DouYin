## 二、背景与目标

### 2.1 背景
用户在浏览网页时普遍受到展示广告、弹窗、信息流广告、视频贴片广告的干扰，影响阅读效率与体验。市场上虽有成熟拦截器，但本项目定位为**小众、轻量、隐私友好**的工具：以"纯本地规则匹配 + 可选匿名统计"为差异化，后期上架主流应用商店，测试期免费。

### 2.2 要解决的问题
- 主流网站展示广告、弹窗、信息流广告干扰阅读。
- 视频平台（如 YouTube、B 站等）贴片/暂停广告影响观看。
- 现有工具或过重、或隐私政策不透明，用户缺乏轻量可信选择。

### 2.3 成功指标与口径

| 指标 | 目标值 | 口径 / 统计周期 | 来源 |
|------|--------|----------------|------|
| 广告拦截率 | ≥ 90%（估算） | 自建 50 站点评测集，拦截成功数 ÷ 广告元素总数；周维度 | 内部评测 |
| 页面加载耗时优化 | 较未拦截降低 ≥ 20%（估算） | 评测集平均首屏完成时间对比；周维度 | 内部评测 |
| 匿名统计上报成功率 | ≥ 95% | 成功上报批次 ÷ 应上报批次；日维度 | 匿名统计后端 |
| 商店 90 日活跃安装 | ≥ 1000（小众目标，估算） | 商店后台活跃安装；上线后 90 日 | 商店后台 |
| PII 泄露事件 | 0 | 安全审计发现的用户浏览 URL / 个人信息外发次数 | 安全审计 |

> 说明：标注"估算"的数值为初期目标假设，待建立评测集与 baseline 后修订。

## 三、名词与术语定义

| 术语 | 定义 |
|------|------|
| MV3（Manifest V3） | Chrome / Edge 现行扩展规范，限制网络请求拦截方式 |
| declarativeNetRequest（DNR） | MV3 提供的声明式网络请求拦截 API，规则上限约 33 万条 |
| Cosmetic Filtering | 通过内容脚本隐藏页面中广告 DOM 元素，而非拦截请求 |
| Filter List（规则列表） | 公开的广告拦截规则集（如 EasyList 等），以特定语法描述匹配规则 |
| 匿名统计 | 去标识化、仅聚合的上报数据，不含用户浏览 URL 与个人信息 |
| 站点白名单 | 用户指定不拦截的域名列表 |

## 四、需求范围

### 4.1 包含（In Scope）
- 网络层广告请求拦截（基于 DNR 规则）。
- 页面广告元素隐藏（Cosmetic Filtering）。
- 全覆盖：展示广告、弹窗、信息流广告、视频贴片广告，及主流大平台（YouTube、B 站等）。
- 规则订阅与静默更新、本地缓存。
- 全局开关、站点级白名单、基础设置。
- 本地拦截统计面板。
- 可选匿名统计上报（默认开启，可一键关闭）。
- 上架 Chrome / Firefox / Edge 商店。

### 4.2 不包含（Out of Scope，本期不做）
- 用户账号系统、自定义规则的云同步。
- 付费 / 捐赠 / 订阅功能（测试期免费，留待后续版本）。
- VPN / 隐私代理 / 反追踪（除广告拦截外的隐私能力）。
- 网页内容改写（除广告元素隐藏外，不修改页面正常内容）。
- 移动端 App 内广告拦截（仅浏览器扩展）。

## 五、方案对比与选型说明

### 5.1 候选方案

| 方案 | 思路 | 实现成本 | 开发复杂度 | 用户体验 | 风险 | 上架可行性 | 综合评价 |
|------|------|----------|------------|----------|------|------------|----------|
| A：MV3 + DNR + Cosmetic + 可订阅规则（推荐） | Chrome/Edge 走 DNR 网络层 + Content Script 隐藏；Firefox 同 MV3；规则内置+订阅 | 中 | 中 | 好 | 中（MV3 上限） | 高（合规上架） | **推荐**：唯一能上架 Chrome 且全覆盖的路径 |
| B：MV2 强拦截（仅 Firefox） | 用 blocking webRequest 实现更灵活拦截 | 低 | 低 | 优 | 低（技术） | 低（Chrome 已禁 MV2） | 备选：仅 Firefox 侧能力增强，无法上架 Chrome |
| C：云端规则 + 本地匹配 | 规则存云端，客户端拉取匹配 | 高 | 高 | 中 | 高（隐私/延迟） | 中 | 不推荐：增加延迟与隐私顾虑，与"隐私友好"定位冲突 |

### 5.2 推荐方案与理由
**推荐方案 A**。理由：
1. 用户明确要求"上架应用商店 + 全覆盖"，MV3 是 Chrome/Edge 上架的唯一合规路径，方案 A 兼容三端。
2. DNR 规则上限约 33 万条，配合 Cosmetic Filtering 可覆盖绝大多数展示/信息流/视频贴片场景；视频贴片通过"拦截广告请求 + 隐藏播放器广告容器"组合处理。
3. 规则订阅机制让社区公开规则集（如 EasyList 等，需确认许可证合规）可直接复用，降低自维护成本。
4. 纯本地匹配 + 可选匿名统计，契合"隐私友好"差异化定位。

### 5.3 演进路径
- 本期（v1）：方案 A 基础能力 + 匿名统计。
- 后续 v2（触发条件：商店安装达 5000 且运营资源就绪）：自定义规则云同步、付费高级规则、反追踪模块。
- 后续 v3（触发条件：v2 验证付费意愿）：账号体系、跨设备同步。

## 六、用户角色与使用场景

### 6.1 用户角色
| 角色 | 身份背景 | 核心目标 | 能力水平 |
|------|----------|----------|----------|
| 普通用户 | 普通上网者，厌烦广告 | 一键清净，无配置负担 | 新手 |
| 进阶用户 | 有一定动手能力的用户 | 自定义白名单、调试误杀 | 熟练 |

> 画像基于通用认知构建，非编造调研数据；上线后由匿名统计与商店评论校准。

### 6.2 用户故事（节选）
- **US-01**：作为普通用户，我想要安装后默认开启拦截，以便无需配置即可清净浏览。
  - Given 首次安装，When 打开浏览器，Then 默认启用全局拦截且状态栏显示已拦截计数。
- **US-02**：作为普通用户，我想要对某站点关闭拦截，以便访问依赖广告的正常功能。
  - Given 某站点功能异常，When 点击"暂停本页/本域"，Then 该域不再拦截且记录到白名单。
- **US-03**：作为进阶用户，我想要查看拦截统计，以便了解效果。
  - Given 已运行一段时间，When 打开统计面板，Then 显示今日/累计拦截数与 Top 被拦域名（聚合）。

## 七、功能需求

> 状态词统一：必须（shall）/ 应该（should）/ 可以（may）/ 禁止（must not）。

### FR-01 网络层广告请求拦截
- 规则：系统必须基于 DNR 规则拦截匹配的广告请求；规则总数应控制在 30 万条以内（留余量防超限）；当订阅规则合计超过上限时，应按近 30 日命中率降序裁剪低价值规则，保留高命中规则。
- 验收（GWT）：Given 启用且规则已加载，When 访问含已知广告域的页面，Then 对应请求被阻断且页面不加载该广告资源。

### FR-02 页面广告元素隐藏（Cosmetic）
- 规则：系统应该使用内容脚本隐藏匹配的广告 DOM 元素（如信息流卡片、贴片容器）；禁止修改非广告的正常页面内容。
- 验收：Given 页面含可隐藏的广告容器，When 内容脚本执行，Then 该容器在视觉上不可见且不占位异常。

### FR-03 规则订阅与更新
- 规则：系统应该内置基础规则并支持订阅 ≥ 1 个公开规则集；应该每 24 小时静默检查更新；更新失败时禁止中断现有拦截；规则下载后、应用前必须校验完整性（哈希），校验失败应限次重试（≤ 3 次）后仍失败则保留旧规则并静默退出本次更新。
- 验收：Given 网络正常，When 到达更新周期，Then 后台拉取并校验后应用新规则，用户无感知；Given 更新失败或校验失败超 3 次，Then 保留旧规则。

### FR-04 全局开关与站点白名单
- 规则：系统必须提供全局启用/禁用开关；必须支持按域名添加/移除白名单；白名单必须持久化。
- 验收：Given 用户将 example.com 加入白名单，When 再次访问该域，Then 该域请求不被拦截。

### FR-05 本地拦截统计面板
- 规则：系统应该在扩展弹窗/设置页展示本地拦截计数（今日、累计、Top 被拦域名聚合）；禁止将统计含 URL 原文上报。
- 验收：Given 已拦截若干请求，When 打开面板，Then 显示计数且不含任何完整 URL。

### FR-06 匿名统计上报（可关闭）
- 规则：系统应该默认开启匿名统计，上报**仅聚合、去标识化**指标（见第十节字段清单）；必须在首次运行时以隐私政策弹窗明示统计内容与关闭方式（告知同意），未经提示不得默认采集；必须提供一键关闭入口；关闭后禁止任何上报。
- 验收：Given 用户关闭统计，When 后续运行，Then 无任何网络上报请求；Given 开启，When 每日上报，Then 仅含聚合计数，不含 PII/URL。

### FR-07 设置持久化与权限最小化
- 规则：系统必须仅申请实现功能所必需的主机权限与 API 权限；主机权限应采用动态申请（declarativeNetRequestWithHostAccess + 用户按需授权），禁止静态声明 `<all_urls>` 过度授权；设置必须持久化到本地存储。
- 验收：Given 用户修改设置，When 重启浏览器，Then 设置保持不变；权限清单与商店声明一致。

## 八、非功能需求

| 类别 | 要求（数值） |
|------|--------------|
| 性能 | DNR 规则数 ≤ 30 万；内容脚本注入不影响页面可交互性（注入耗时目标 < 50ms，估算）；扩展内存占用 < 150MB（估算） |
| 安全 | 权限最小化；规则源需校验（哈希/签名）；匿名上报传输加密（HTTPS）；禁止读取页面表单/密码字段 |
| 兼容 | 支持 Chrome / Edge（MV3）、Firefox（MV3）；覆盖近 3 个主版本 |
| 可访问性 | 设置页关键操作支持键盘可达与读屏朗读；文字对比度满足基本可读性 |
| 稳定性 | 扩展崩溃率 < 0.1%（估算）；规则更新失败不影响现有拦截 |

## 九、业务流程与状态流转

### 9.1 规则更新状态机
```
[空闲] --定时/手动检查--> [检查更新]
[检查更新] --有更新--> [下载]
[下载] --校验失败--> [保留旧规则, 重试] --> [空闲]
[下载] --校验成功--> [应用新规则] --> [生效] --> [空闲]
[检查更新] --无更新--> [空闲]
```

### 9.2 扩展启用状态机
```
[全局启用] --用户禁用--> [全局禁用]
[全局启用] --站点加白--> [站点局部放行]
[站点局部放行] --移除白名单--> [全局启用]
```
> 状态单向/可逆流转，禁止"已禁用"状态下静默恢复拦截（需用户主动操作）。

## 十、数据与埋点需求

### 10.1 埋点事件（本地）
| 事件名 | 触发时机 | 上报字段（本地） |
|--------|----------|------------------|
| ad_blocked | 每次成功拦截请求/隐藏元素 | 规则来源、域名（仅聚合用，不上报原文）、时间戳 |
| rule_updated | 规则更新成功 | 版本号、规则条数 |
| stats_opt_out | 用户关闭匿名统计 | 无附加 PII |

### 10.2 匿名统计上报字段清单（仅聚合、去标识化）
| 字段 | 说明 | 是否含 PII/URL |
|------|------|----------------|
| device_id | 随机生成、可重置的匿名标识 | 否（去标识） |
| date | 日期 | 否 |
| total_blocked | 当日拦截总数（聚合） | 否 |
| top_domains | Top 100 被拦域名（聚合计数） | 否（不含完整 URL） |
| rule_hit_distribution | 各规则列表命中占比 | 否 |
| client_version | 扩展版本 | 否 |

**禁止上报**：用户浏览的完整 URL、搜索词、表单内容、设备精确信息、IP（除非经脱敏聚合且获告知同意）。

### 10.3 指标口径
- 拦截率 = 评测集拦截成功数 ÷ 广告元素总数（周维度）。
- 上报成功率 = 成功上报批次 ÷ 应上报批次（日维度）。

## 十一、权限与安全要求

### 11.1 权限清单（最小化）
- `declarativeNetRequest` / `declarativeNetRequestWithHostAccess`：网络层拦截。
- `storage`：设置与规则缓存持久化。
- `host_permissions`：按需匹配（避免 `<all_urls>` 过度声明，采用按需授权或限定范围）。
- 禁止申请 `webRequestBlocking`、`tabs` 读取页面内容等超限权限。

### 11.2 数据安全
- 匿名 device_id 本地随机生成、与设备真实身份无关；用户可在设置中"重置标识"，重置后新旧标识不可关联，历史聚合数据不可回溯至新标识。
- 所有上报经 HTTPS；服务端仅存储聚合数据，原始上报日志最短留存 ≤ 30 日（估算）后清理。
- 规则源下载需校验完整性（哈希），防止规则被篡改注入恶意匹配。

### 11.3 数据合规专项（匿名统计触发，必带 8 项）
1. **数据分类分级**：匿名统计属"低敏感聚合数据"，不含 PII，定级最低。
2. **告知同意**：安装/首次运行时以隐私政策与授权弹窗明示"匿名统计默认开启及可关闭"；关闭即停。
3. **最小化收集**：仅采集第十节列出的聚合字段，不含 URL/PII。
4. **去标识化**：device_id 随机化、可重置；服务端不关联真实身份。
5. **用户权利**：提供"重置标识""一键关闭统计"；后续版本补充"数据删除申请"入口。
6. **留存清理**：原始日志 ≤ 30 日（估算）清理，仅保留聚合结果。
7. **审计**：统计后端记录访问日志，定期安全审计，目标 PII 泄露事件 = 0。
8. **跨境**：本期统计后端部署于国内/合规区域，不涉及个人数据跨境传输；若后续出海再补跨境合规专项。

## 十二、异常处理清单

| 异常场景 | 处理方式 |
|----------|----------|
| 规则更新下载/校验失败 | 保留旧规则，静默重试（限次），不阻断现有拦截 |
| 规则导致页面功能异常（误杀） | 用户可"暂停本页/本域"；提供误杀反馈入口；规则源回滚机制 |
| DNR 规则数接近上限 | 按命中率裁剪低价值规则，保留高命中规则 |
| 网络断开 | 本地规则继续工作，统计延后上报或丢弃 |
| 匿名上报失败 | 静默丢弃，不阻塞主流程，不重复重试轰炸 |
| 商店审核驳回 | 按驳回理由调整权限声明/隐私政策，记录变更 |

## 十三、上线计划、依赖与上线后验证

### 13.1 依赖评估（三档）
| 依赖项 | 所属 | 就绪状态 | 分级 | 最晚就绪时限 | 影响与替代 |
|--------|------|----------|------|--------------|------------|
| 公开规则列表源（如 EasyList 等） | 第三方开源 | 可用，需确认许可证 | 阻塞 | 上架前 | 替代：自维护基础规则（覆盖下降） |
| 商店开发者账号（Chrome/Firefox/Edge） | 平台 | 待注册 | 阻塞 | 上架前 | 无替代，必须先完成 |
| 匿名统计后端 | 自研 | 需开发 | 并行 | 内测前 | 替代：先关闭统计上线，后续补 |
| 评测集（50 站点） | 自研 | 待建 | 并行 | 上线前 | 替代：人工抽样验证 |

### 13.2 上线计划
1. 内测（小范围）：完成核心拦截 + 本地统计，验证 MV3 覆盖率。
2. 商店提交：按各平台规范提交，附隐私政策与权限说明。
3. 灰度：先小比例开放，监控拦截率与崩溃率，再全量。

### 13.3 上线后验证
- 拦截率评测集周维度监控。
- 商店评论与误杀反馈收集。
- 匿名统计上报成功率与零 PII 泄露审计。
